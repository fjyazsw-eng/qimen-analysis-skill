# 股票未来十个实际交易日预测

本规则用于用户明确询问某只股票、ETF 或可交易证券未来十个实际交易日的盘面趋势。它借鉴六爻实战报告的“先定总体、再按时间轴逐日列触发与结果”格式，但底层判断仍统一使用奇门取用、宫位、门星神干、旺衰、生克、特殊状态和应期证据；不得把六爻世应、六亲、日月建或动爻规则改名后套入奇门。

## 一、正式预测前置门槛

股票十日预测必须先完成现实市场核验，再进入正式逐日推演。若当前运行环境具备联网或外部行情访问能力，必须使用；不得跳过现实核验直接生成正式十日表。

最低核验项：

- 标的名称、代码、交易所与证券类型。
- 当前日期与预测起点：从下一个实际交易日开始，还是包含尚未收盘的当日。
- 最近可得价格、近期走势、成交量/成交额、相对板块或指数强弱。
- 重大已知公告、停复牌、监管、财报或其他足以改变短期交易状态的事件。
- 未来十个**实际交易日**的交易日历；必须排除周末、法定休市和已知停牌日。

现实数据源优先级：交易所/上市公司公告 > 权威证券数据源 > 主流财经行情源 > 其他可验证来源。不同来源冲突时说明口径，不静默拼接。

若环境无法联网或无法可靠确认未来十个实际交易日：

- 只能给“术数总体趋势草案”，明确标注“现实市场尚未核验”；
- **不得输出正式十日逐日预测表**；
- `T+1～T+10` 仅可作为内部推演序号，不作为面向用户的正式最终输出；
- 不得编造交易日期、停牌状态、价格、涨跌幅、成交量或日干支。

## 二、目标事件与取用

目标事件固定为“未来十个实际交易日内该标的每日收盘方向、日级强弱与阶段转折倾向”，不是用户账户盈亏，也不是具体买卖指令。

- 日干：求测者/决策主体，只用于承载和风险适配。
- 时干：本次标的或交易事项主用；角色必须明确。
- 生门：收益与价格上行通道。
- 甲子戊：资金、承接与量能基础。
- 值符、值使及相关门星神干：市场主导力量、执行通道和表现方式的修正。
- 现实价格、量能、公告和指数环境：独立现实证据层，不得伪装成盘面事实。

预测标的走势时，必须以“标的/事项主用 + 生门 + 资金承接 + 宫际动力”为核心，不能只分析日干，也不能只见生门便断上涨。

## 三、双轨证据链

正式分析必须保留两条独立证据链，最后再做交叉验证：

### A. 奇门预测层

先冻结原局判断，不受用户成本、已知后续结果或技术面结论反向污染：

1. 原局确定十日总体结构与主要动力/阻力。
2. 明确标的主用宫、生门宫、甲子戊资金宫及关键值符值使宫。
3. 识别空亡、门迫、入墓、击刑、马星、伏吟/反吟等高相关结构，但不得单项定吉凶。
4. 形成十日事件链：蓄势/承压 → 启动 → 延续/加速 → 转折 → 整理/再选择方向。

### B. 现实市场层

独立记录：

- 最新价格与近阶段趋势；
- 量价结构；
- 板块/指数相对强弱；
- 重大公告和交易状态；
- 可验证的技术关键位只作为现实观察线，不得伪装成奇门结论。

### C. 交叉验证层

只允许使用：`呼应 / 部分呼应 / 冲突 / 现实证据不足`。

现实行情可以降低或提高最终执行置信度，但不得回头篡改已经冻结的奇门原始预测。若两层冲突，必须同时保留，并写明“以现实风控优先”。

## 四、实际交易日逐日推演

正式十日表必须使用**具体日期 + 星期**，不得以 `T+N` 代替最终日期。

对未来十个实际交易日中的每一天，必须独立完成以下步骤：

1. 确认该日确为实际交易日。
2. 取得并核验该日干支；无法可靠取得时，不得伪造。
3. 检查当日干支对原局核心宫、标的主用、生门、甲子戊资金宫与事件链的触发。
4. 检查与核心宫相关的五行生克、冲、合、刑、墓、空亡填实/冲空、马星等是否形成有效增强、削弱或转折信号。
5. 将“原局静态结构”与“当日动态触发”分开记录，再综合成该日唯一首要方向。
6. 现实市场验证信号单列，不得把技术面条件冒充为日期干支触发。

**禁止行为：**

- 禁止先定“先弱后强”，再机械把前几天写弱、中间几天写强。
- 禁止为了让十日曲线平滑而人为分配强弱。
- 禁止只凭一个日干五行或一个冲合直接定该日涨跌。
- 禁止把周末、休市日或停牌日排入十日表。

连续数日可以组成阶段链，但每一日都必须有自己的独立触发证据。若某日证据不足，必须写“证据不足，无法可靠判断”，而不是用“横盘整理”掩盖缺失。

## 五、统一方向词表

逐日“方向”只能使用以下五类：

- **强势上行**：上行动力占明显优势，预计收盘方向偏上且波动可能放大。
- **偏强整理**：偏上或抗跌，但推进力度有限。
- **横盘整理**：方向优势不足，主要表现为区间消化；不得把它当作逃避判断的默认项。
- **偏弱整理**：承接不足或压力偏强，预计收盘方向偏下但未形成明显加速。
- **明显下行**：下行动力占明显优势，预计收盘方向偏下且风险可能放大。

“方向冲突”“有涨有跌”“注意波动”不能单独充当方向结论。实在无法形成方向时必须直写“证据不足，无法可靠判断”，说明缺失项。

强度只能使用 `强 / 中 / 弱`；置信度继续使用 `高 / 中高 / 中 / 中低 / 低`。方向、强度和置信度是三个不同维度，不得混写。

## 六、固定输出

股票预测仍先使用通用【定性评价】，随后在正式十二段的“未来趋势、应期与时间窗口、策略、风险”栏目中嵌入以下固定内容。

即使用户要求“大白话、简单说、只给结论”，十行逐日表也不能省略；简版只压缩取用解释和证据展开。

### 固定图片信息结构

默认图片应尽量在单张竖版信息图内包含以下模块，顺序保持稳定：

1. **标题区**：标的名称、证券代码、预测区间、局式日期。
2. **现实行情快照**：数据时间、最新价、近期趋势、量价状态、相对板块/指数强弱；只放已联网核验的数据。
3. **奇门十日总览**：总体定性、十日主路径、最可能启动/转折/风险日期、最终置信度。
4. **十日节奏图**：横轴为十个实际交易日期；强弱只由冻结逐日表映射，并注明“相对节奏，不是股价预测”。
5. **关键观察区**：只展示现实数据或正式分析中已经确认的关键价格/技术区域及其含义；没有可靠价格依据时整个区块省略。
6. **十日逐日表**：日期、星期、方向、强度、核心验证信号/观察重点；必须覆盖全部十个实际交易日。
7. **持仓适配区**：若用户提供成本与持仓，可显示“成本/持仓背景 + 风险观察策略”，但不得改变原始走势预测，也不得生成具体仓位、杠杆或保证性买卖指令。
8. **底部结论与风险声明**：用一句话突出最重要窗口，并注明术数预测与市场风险边界。

固定的是**信息架构和数据一致性**，不是像素级模板。允许根据内容长度、屏幕比例和标的特征调整排版、字体层级和视觉样式；不得为了套版删除关键日期或压缩到难以阅读。

### 图片/图表一致性要求

- 横轴必须使用十个实际交易日期，不使用 `T+N`。
- 图上必须标注关键启动、转折、风险日期。
- 若使用“强弱指数”作可视化，只能来源于已经完成的逐日方向/强度映射，并明确注明“相对节奏，不是股价预测”。
- 不得在图表中虚构目标价、涨跌幅、日内高低点。
- 默认图片和用户明确要求的图片都必须把已冻结的逐日表转换为信息图，禁止重新生成另一套预测。
- 图片生成前必须先完成并冻结文字逐日表；不得让图片模型自行补日期、行情、目标价、涨跌方向或应期。
- 图片中任何数字、日期、方向和结论若与文字底稿冲突，以文字底稿为准，并应重新生成图片纠错。
- 图片不得把“观察条件”视觉包装成确定买卖指令。

## 七、准确表达与金融边界

- 方向必须明确，但不能使用“一定涨、必跌、百分之百”。
- 没有可靠价格模型时，不报具体目标价、涨跌幅、涨停或跌停概率。
- 不因用户持仓成本改变盘面方向结论；账户盈亏与标的走势分开。
- 不直接给买入、卖出、加仓、减仓、做多、做空、仓位或杠杆指令。
- 可以给观察、核验、风险暴露和失效条件；现实公告、停复牌、财报、监管和市场数据优先。
- 同一盘、同一标的、同一预测起点的奇门十日表必须前瞻冻结；新公告、新行情或新局出现时按多局规则追加“现实修正”或“新局修正”，不得覆盖旧表。
- 复盘时必须区分：原始奇门预测、当时现实市场快照、最终执行建议、事后结果和【后验发现】。

## 八、1.2.4 简洁交付与固定图片模板（强制）

### 8.1 默认用户正文：只交付三项
除非用户明确要求“详细分析 / 分析过程 / 理论依据 / 教学模式”，股票/ETF正式预测的默认用户可见正文**只允许**保留：

1. 【定性评价】：等级 + 一句话 + 核心判断 + 建议；
2. 【未来十个实际交易日简表】：只保留 `日期｜可能走势｜建议` 三列，共十行；
3. 一张固定格式的“奇门股票操作建议图”。

现实市场快照、取用、宫位证据、逐日干支触发、奇门×现实比对、置信度、失效条件等仍必须在分析阶段完整完成并冻结，但默认不展开给用户；用户索要分析过程时再按完整 SOP 展开。

简表中的“可能走势”必须从正式冻结逐日表的五级方向原样映射，不得另起一套措辞导致方向改变。建议必须是简短的观察/风险动作表达，不得把术数预测包装成确定性交易指令。

### 8.2 图片视觉模板锁定
默认图片固定采用用户确认的“金融仪表盘”表达，不再自由切换为九宫盘、长篇报告、卡片海报或其他布局。固定特征：

- 横向 16:9 单页信息图；
- 深蓝色总标题栏，白底主体，红色模块标题栏；
- 上半区三栏：`当前行情｜奇门十日节奏曲线｜关键价格区域`；
- 下半区：左侧大表 `未来十个交易日情况简表`，右侧依次为 `卦象定性判断｜操作建议/总体结论`；
- 十日表在图片中同样只保留 `日期｜可能走势｜建议`，不得恢复复杂证据列；
- 必须显著显示【卦象定性判断】及九级等级原文，例如“平偏凶”；不得改写为“偏凶”“平偏吉”等近义等级；
- 若没有可靠关键价位依据，可将“关键价格区域”替换为“关键观察信号”，不得编造价格。

### 8.3 冻结字段白名单与零推理图片协议
在调用任何图片生成器之前，必须先生成一个“图片冻结字段清单”。图片只允许排版这些字段，**零推理、零补全、零改写结论**。冻结字段至少包括：

- 标的名称、代码、局式时间；
- 行情数据时间与已核验行情数字；
- 【定性评价】等级原文；
- 十个实际交易日期；
- 每日可能走势；
- 每日建议；
- 重点日期；
- 已确认的关键价格区域或观察信号；
- 一句话总体结论。

图片模型不得自行：

- 改变九级定性等级；
- 改变任何一天的方向或建议；
- 新增/删除/错排交易日期；
- 把“偏强整理”升级成“强势上行”，或把“偏弱整理”改成“修复”；
- 自行生成目标价、止损价、买卖价、仓位、涨跌幅、星级评分；
- 根据视觉美观重新安排预测节奏；
- 把用户成本价反推成目标价。

### 8.4 图片发布前强制一致性检查
图片生成后，在向用户展示前必须逐项核对以下字段：

`定性等级 → 十个日期 → 十日方向 → 十日建议 → 重点日期 → 关键价位/观察信号 → 总体结论`。

任意一项与冻结文字底稿不一致：

- 该图片判定为**无效图片**；
- 不得把错误图片作为正式结果；
- 必须重新生成；
- 不得用“图片仅供参考”掩盖数据冲突。

若当前图片生成能力无法可靠保证文字/数字一致性，则**宁可只输出文字简表，不生成错误图片**。准确性优先于图片交付。
