股票分析前必须读取仓库根目录 `DATA_SOURCES.md`：hithink-finance 为唯一主源，AKShare 新浪分钟线仅补充分钟线；禁用 Tushare 和其他自动回退，失败或能力缺失明确报错。起局/起卦之后的数据仅可用于复盘；未来交易日历或公告原文若主源不支持，明确记为无法验证，不得编造。
# 股票未来十个实际交易日预测

本规则用于用户明确询问股票、ETF 或其他可交易证券未来十个实际交易日走势。底层只使用奇门取用、宫位、门星神干、旺衰、生克、特殊状态、应期与现实市场证据；六爻只可借鉴逐日时间轴的表达形式，**不得把六爻世应、六亲、日月建或动爻规则混入奇门证据链**。

## 一、前置门槛

正式十日预测前必须先核验：标的名称/代码/交易所、**奇门起局时间**、起局前可获得的现实行情与数据时间、近期量价、板块或指数相对强弱、重大公告/停复牌/监管事项，以及起局之后未来十个实际交易日。

正式用户日期必须使用**具体日期 + 星期**。若无法联网或无法可靠确认交易日历，只能给总体趋势草案，不得编造正式十日表、价格、涨跌幅、停牌状态或日干支。

### V1.2.7 预测时间轴冻结规则（最高优先级）

1. **预测起点 = 奇门起局时间，不是用户后续提问时间。**
2. 现实信息只允许用于核验**起局时点之前**的市场状态是否与盘面呼应；起局之后才出现的行情、公告、消息不得参与原始奇门定性和十日方向生成。
3. 若起局发生在收盘后、休市日或非交易时段，`T+1` = 起局之后的第一个实际交易日。
4. 若起局发生在交易时段内，默认仍从下一个完整实际交易日开始；只有用户在起局时明确询问“当日剩余时段/当日收盘”时，才允许把当日纳入独立事件窗口。
5. 十日窗口一经按起局时间确认即冻结。用户数日后再次提问、补充持仓、要求复查或复盘，不得把窗口整体向后滚动。
6. 若当前提问时间已晚于起局时间，窗口内已发生的交易日仍保留在原十日表原位置：分别记录**冻结预测**与**实际结果**；不得删除已发生日期后再向后补足十个未来日期。
7. 起局后已经发生的数据只能进入【事后验证/复盘层】，不得反向修改已经冻结的九级定性、十日主趋势、逐日方向、关键转折或原始应期。
8. 标准执行顺序固定为：

`起局时点冻结 → 核验起局前现实信息 → 确认起局后十个实际交易日 → 独立生成原始十日预测 → 对已发生日期做事后验证 → 对未发生日期保留前瞻预测`

任何“按当前提问时间重新起算 T+1”“先看后续行情再反推原预测”“删除已发生交易日并向后补十日”的做法均视为时间轴错误。

## 二、固定取用与证据链

股票走势的核心证据固定为：

- 标的/交易事项主用；
- 生门：收益与上行通道；
- 甲子戊：资金、承接与量能基础；
- 值符、值使及核心宫：主导力量和落实通道；
- 宫际生克、资源流向、旺衰与特殊状态：用于综合修正；
- 现实行情：独立现实层，不伪装成盘面事实。

不得只看日干、只见生门、只见吉门/凶门，或只凭空亡、入墓、击刑、门迫、伏吟、反吟、马星决定最终方向。

## 三、分析稳定性

股票专项强制遵守[分析稳定性与冻结协议](../../rules/analysis-stability.md)。

正式分析顺序固定：

`分析指纹 → 取用 → 证据账本 → 五问方向闸门 → 卦象九级定性 → 十日主趋势 → 每日独立触发 → 十日逐日方向 → 现实市场比对 → 用户建议 → 图片冻结字段`

后一步不得反向改写前一步。

### 同盘同问强制规则

同一局式、同一标的、同一预测起点、同一问题范围、同一 Skill 版本：

- 取用必须相同；
- 主支持/主阻力证据顺序必须稳定；
- 九级卦象定性必须相同；
- 十日主趋势、关键转折与逐日原始方向必须相同。

只有盘面更正、主体/目标/范围改变、新局修正或版本规则实质变化时才允许改变；否则视为**分析漂移**，必须回退到既有冻结结论。

现实行情变化、用户成本和持仓只允许影响现实比对、关键区域和行动建议，不得把同一卦象从“平偏凶”改成“平偏吉”，也不得反向改写已经冻结的十日原始方向。

## 四、逐日推演

未来十个实际交易日必须逐日推演，每一天独立检查日期干支对标的主用、生门、资金宫、核心宫及事件链的触发，并综合生克、冲合、刑墓、空亡填实/冲空、马星等。

禁止：

- 从“先弱后强”等总体趋势机械分配每日涨跌；
- 为了曲线好看人为平滑；
- 只凭单一日干、冲合或五行关系定方向；
- 把休市日、周末或停牌日排入十日表。

证据不足时直写“证据不足，无法可靠判断”，不得用横盘整理掩盖缺失。

## 五、统一方向词表

逐日方向只允许：

- **强势上行**
- **偏强整理**
- **横盘整理**
- **偏弱整理**
- **明显下行**

方向、强度和置信度是不同维度。默认用户简表只显示方向，不把内部置信度和证据列堆给用户。

## 六、固定交付

默认用户交付固定为：第一部分文字情况 + 第二部分固定六模块图片（环境支持时）。

### 第一部分｜文字情况

```markdown
【定性评价】
等级：九级原文
一句话：
核心判断：
建议：

【未来十个实际交易日】
| 日期 | 可能走势 | 建议 |
|---|---|---|
| YYYY-MM-DD 周X | 五级方向原文 | 简短观察/风险动作 |
| ...共十行... | | |

【关键提示】
- 重点日期：最多 3 个
- 总体节奏：一句话
- 现实冲突/失效条件：存在时才写
```

硬约束：十日表恰好十行实际交易日；“可能走势”必须逐字来自冻结五级方向；九级等级是冻结的卦象定性；默认不展开取用、宫位、逐日干支触发、置信度、现实市场快照或奇门×现实比对；用户明确要求详细分析/教学/依据时再展开。

### 第二部分｜固定六模块图片

除非用户明确说不要图片/只要文字，环境具备能力时同时生成横向 16:9 金融仪表盘。六模块固定为：当前行情、奇门十日节奏曲线、关键价格区域/观察信号、未来十个交易日情况简表、卦象定性判断、总体结论&关键提示。图片必须与冻结文字底稿同源，不得重新推理。

## 七、金融边界

- 不使用“一定涨、必跌、百分之百”。
- 没有可靠价格模型时，不报目标价、涨跌幅或涨跌停概率。
- 不因持仓成本改变标的原始走势判断。
- 不把术数预测包装成确定性买卖、仓位或杠杆指令。
- 现实公告、停复牌、财报、监管和市场数据优先用于风控。
- 新行情只能追加现实修正；新局按多局规则追加新局修正，不覆盖旧预测。
