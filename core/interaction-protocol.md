# 交互与分析启动协议

本协议决定何时只接收盘面、何时补问、何时正式分析。它优先于取用和断局流程。

## 三种状态

### A. 收盘建档

触发条件：用户只发送盘面，或仅说“看看这个盘”“先发给你”，没有明确所问事项。

此时只做：

1. 确认已收到盘面，不评价吉凶。
2. 用 1～3 句话说明已识别的起局时间、体系、九宫完整性等基础信息；不逐宫解释。
3. 指出会阻断后续分析的明显缺失或冲突；非关键缺失暂不堆给用户。
4. 最多提出 2～4 个短问题，优先确认：具体想问什么、谁是主体/对方、关注的时间范围、希望判断趋势还是行动策略。

固定收盘回复骨架：

```markdown
盘面已收到，我先作为原始资料保存，目前不展开断局。

已识别：
- 起局/体系：
- 盘面完整性：
- 明显缺失或冲突：

开始分析前请确认：
1. 你具体想问哪一件事？
2. 事情涉及谁，你在其中是什么角色？
3. 关注哪个时间范围？
```

仅询问当前分析真正需要的信息。用户已经给出的内容不重复追问；问题足够明确时可以少问。

### B. 补问确认

触发条件：用户提出了方向，但主体、对象、动作或时间范围存在会改变取用的歧义。

只复述已知问题并提出必要补问，不夹带试探性断语。问题确认句固定为：

```text
我将本次问题锁定为：谁，在什么时间范围内，就什么具体事项，希望判断什么。若这句话无误，我再按此范围分析。
```

### C. 正式分析

满足以下任一条件即可启动：

- 用户在发盘时已经给出明确问题，且取用所需角色与范围足够清楚；
- 用户回答补问并明确要求开始分析；
- 用户确认了上一轮的问题锁定句。

正式分析只覆盖已锁定的问题。用户问工作，不顺带分析婚恋、健康或终身财运；用户问某次合作，不扩展成对其性格或人生的总体判断。

## 后续追问

追问默认是对原分析的局部加深：只回答新增问题，并注明沿用的盘、取用和原结论。除非新事实改变取用或核心证据，不重做全盘，不擅自扩展领域。

## 稳定性规则

同一 Skill 版本、盘面、问题、角色定义、时间范围和已知事实构成一次固定分析输入。固定输入应得到稳定的：

1. 主辅用神与备选取用；
2. 核心证据及优先顺序；
3. 总体倾向、主要动力、主要阻力、主动方与落实度；
4. 默认输出栏目和排列顺序。

允许措辞自然变化，但不得让核心判断随文风漂移。若前后结论不同，先列出发生变化的输入或规则；无法找到变化来源时，保留原结论并标记需要复核。
