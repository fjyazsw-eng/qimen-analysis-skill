# 前瞻案例协议

当前真实案例数为零。本协议用于以后获得案例时防止事后解释污染。

## 1. 建档与冻结

1. 生成匿名 `case_id`，保存用户原问题和原始盘面。
2. 在结果未知时完成 `analysis.md`，记录分析时间、Skill 版本、定性等级、主结论、条件、策略与不确定部分。
3. 按[预测台账](../cases/prediction-ledger.md)冻结目标事件、事件阶段、未来路径、候选窗口、置信度、验证信号与失效条件。
4. 对 `input.md` 和 `analysis.md` 计算文件哈希并写入案例记录；冻结后不得改写，只能追加更正说明。

## 2. 结果记录

事情出现结果后才创建 `outcome.md`，使用[结果记录模板](../cases/outcome-template.md)：

- 区分客观证据、当事人陈述和主观感受。
- 记录结果发生与获知日期。
- 未完成、改变目标或外部条件显著变化时，不强行判定命中/失误。
- 新局只能追加与旧预测的强化、削弱、修正、推迟、提前或反转关系。

## 3. 独立复盘

使用[复盘模板](../cases/review-template.md)，逐条比较事前结论与结果：

- 正确、部分正确、错误、不可验证分别登记。
- 原预测未提及、只在结果出现后发现的依据标为【后验发现】，不计命中。
- 错误归入既有错误类型；不因单例立即修改通用规则。
- 只有跨案例重复出现、能解释明确失败机制的模式，才提出规则变更候选。

## 4. 回归注册

经脱敏和复核后，在 `tests/regression-cases.yaml` 登记案例。规则变更前后都运行相关案例，防止修复一个问题却破坏其他模块。

## 5. 发布纪律

- 没有足够、连续、事前冻结且结果可验证的案例时，`accuracy_claim_allowed` 保持 `false`。
- 不筛选只展示成功案例，不删除失败案例，不用主观反馈代替客观结果。
- 即使未来形成统计，也必须公开样本定义、排除标准、未决案例和误差类型。
- 各应期证据必须按规则编号分别统计样本量、问题类别、窗口误差与失败案例；不得用传统地位替代命中率。
