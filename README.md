# 奇门遁甲实战分析 Skill

一个面向长期迭代与真实案例回归的 Codex Skill。它不负责排盘，而是读取已经排好的结构化局式，稳定完成：输入核验 → 问题定义 → 取用 → 定性评价 → 状态与动力 → 未来预测 → 候选应期 → 决策趋避 → 前瞻冻结与复盘。

## 当前版本：V1.2.2

V1.2.2 在 V1.2.1 股票十日格式上补强现实市场核验与日期纪律：正式预测必须先核验最新行情、重大事件和未来十个实际交易日，再逐日依据日期干支对核心宫、标的主用、生门与资金宫进行独立动态触发推演；最终使用具体日期与星期，不以 T+N 代替。新增奇门原始预测/现实市场双轨比对和图表一致性要求。现有 171 个合成场景检查行为边界。本版本不表示股票预测有效性已经得到真实案例验证。

**建设进度：100%（V1.2.2 当前基线）**。当前真实案例为零，股票逐日方向、应期触发、连续触宫、定性和策略规则仍需前瞻回测。

## 输入约定

输入至少应包含起局时间、四柱、阴阳遁与局数、旬首、值符、值使，以及九宫中每宫的神、星、门、天盘干和地盘干。寄干、空亡、马星、旺衰及其他特殊结构应按“无 / 未提供 / 具体值”明确区分。完整字段见 [输入核验](core/input-validation.md)。

推荐同时提供排盘体系、八神体系、天禽处理、标注来源、检测状态和工具版本。特殊状态使用“具体值 / 无 / 未检测到 / 未提供 / 待复核”区分；十二长生的墓与奇门入墓分开记录。完整约定见[结构化局式输入契约](core/structured-input-contract.md)。

原始排盘、结构标注和 AI 推断必须分层保存。Skill 不会为了完成分析而重新排盘或补造缺失值。

## 使用方式

在 Codex 中调用 `$qimen-analysis-skill`，同时提供已排好的结构化局式、明确的现实问题、必要的人物关系/时间范围/已知事实；涉及多人区分或代问时，再提供相关年命信息。

如果只发送盘面而没有提出明确问题，Skill 默认只接收和核验信息，不会主动分析未问内容。正式分析始终先给 4～8 行【定性评价】，再按固定十二段输出；同一版本下，同盘同问且事实未变时，等级、主结论和证据顺序应保持稳定。

### 股票十个交易日预测

用户明确询问某只股票或 ETF 未来十个交易日时，除通用十二段外，固定增加：

- 十日主趋势及一句话路径；
- 先联网核验最新行情、重大事件与未来十个实际交易日；
- 十个具体日期 + 星期的逐日预测；
- 每日唯一首要方向：强势上行、偏强整理、横盘整理、偏弱整理或明显下行；
- 每日独立的日期干支/核心宫动态触发、强度、现实验证信号和置信度；
- 奇门原始预测与现实市场的呼应/冲突比对；
- 与逐日表完全一致的日期图表/图片（运行环境支持时）；
- 最可能启动、转折和风险节点；
- 上下行强化条件与原预测失效条件。

六爻仅作为逐日时间轴的表达参考，底层仍按奇门证据链判断。Skill 不编造休市日、停牌日、价格和涨跌幅，也不把走势预测变成具体买卖、仓位或杠杆指令。

## 本地验证

运行：

```text
python scripts/validate_skill.py
```

验证器不依赖 PyYAML，会检查 UTF-8、Skill 头信息、内部链接、模块路由、场景结构与唯一编号、覆盖基线、案例模板版本及未完成占位。它不能验证术数判断是否准确。

## 维护原则

- 新规则必须注明适用体系、证据来源或案例依据；存在流派差异时并列说明，不静默混用。
- 规则变更应先在脱敏历史案例上回归，再调整稳定内核。
- 事前分析与事后复盘分开保存，禁止用结果污染原始判断。
- 尚未选择开源许可证；发布后继续维护许可证选择、贡献规范和案例隐私策略。
