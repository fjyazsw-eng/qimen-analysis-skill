# 通用奇门候选应期系统 V1

本文件处理“已起之局所问事件何时可能发生”，是应期的唯一权威规则源。主动比较用户提供的未来候选盘仍进入[择时方位模块](../modules/timing-direction/README.md)。本系统产生候选窗口，不承诺必应，也不重新排盘。

## 一、先定义目标事件 E

预测时间前必须把“什么算应”写成可观察事件，并放入[专项事件链](event-chain-templates.md)。想到不等于联系，讨论不等于审批，反弹不等于反转，线索不等于找到。目标不清且会改变触发对象时先最小补问。

## 二、选择现实时间尺度

先区分两个概念：

1. **趋势尺度**：回答事情在短期、中期、中长期、长期分别如何发展。
2. **应期窗口**：回答某个已经定义清楚的可观察事件 E 何时最可能发生。

两者不得混为一谈。可以有明确的长期趋势，但没有足够证据给出长期精确应期。

根据事件速度选 `时 / 日 / 旬 / 月 / 季 / 年`：盘中交易偏时日，短期消息偏日旬，工作调动与关系发展偏旬月，重大项目偏月季，长期职业/婚姻/关系结构可进入月年。用户给出的期限和制度流程优先；不得把所有事项压成几天。

当用户询问“以后、长远、未来几年、长期发展”或问题天然跨越多个周期时，预测层至少检查：

- **短期**：当前直接发展阶段；
- **中期**：一个主要现实周期后的变化；
- **中长期**：结构能否稳定、经验/关系/资源能否兑现；
- **长期**：该路径总体偏增益、维持还是消耗。

具体单位由专项和现实流程决定，不机械把四层固定成同一组月份/年份。

## 三、建立证据池

从与 E 直接相关的主用、辅用和事件节点宫中筛选：

1. 用神落宫对应支、核心宫被值日/值时触发；
2. 对宫冲动、合宫/合支；
3. 空亡出空、填实、冲空；
4. 入墓、冲墓、出墓；
5. 马星、冲马；
6. 值符、值使；
7. 门、星及其旺衰变化；
8. 天盘干、地盘干、干合及已经核实的冲刑规则；
9. 伏吟、反吟、宫际生克；
10. 节气/月令变化；
11. 多个核心用神连续触发；
12. 同一事项连续局重复出现的时间信号。

上述均是候选证据，不默认等权。原局明确字段可进入主轨；程序候选和未人工复核结构只能进入敏感性轨。存在流派差异的规则按[规则可信度](rule-confidence.md)降级。

## 四、候选生成与交叉验证

1. 先由高相关核心宫生成宽窗口，再用时间尺度收窄。
2. 将同一来源的重复标注只计一次；“空亡 + 出空”不是两个独立证据。
3. 高置信候选需要多个独立体系的证据交叉，例如核心宫触发 + 动力关系改善 + 现实流程节点。
4. 单一冲、合、空、马或地支只能列为低置信候选，禁止直接报必应日。
5. 现实条件不具备时，即使盘面触发也只能对应较早事件节点或保持候选。

## 五、连续触宫与事件链

当不同日期依次触发人物宫、关系/流程宫、事情宫时，应优先检验其是否对应“人物变化 → 互动/审批 → 事情落实”的连续链，而不是机械报三个独立结果。顺序与事件链吻合、各节点有独立证据时，整体价值高于孤立触发；顺序不符则降级，不强拼。

## 六、窗口与置信度

默认输出第一、第二候选窗口，必要时第三个，最多三个。多尺度趋势不会增加应期窗口数量；不得为了覆盖短期/中期/长期而每层强凑一个日期。置信度使用 `高 / 中高 / 中 / 中低 / 低`：

- 高/中高：至少有多个独立证据，目标事件、时间尺度和现实条件一致，且无重大冲突。
- 中：有两类支持但仍依赖条件，或存在可管理分歧。
- 中低/低：单一证据、未复核候选结构、尺度不稳或现实条件不足。

在真实前瞻案例形成前，不得把任何通用触发法视为已验证高准确率；“高”只表示本次证据集中度相对高。

固定窗口字段：

```markdown
【时间】
【可能对应事件】
【依据】至少列核心依据 1、2、3；不足三项时降低置信度
【置信度】
【现实验证信号】
【失效条件】
```

证据高度集中于一天时可说“其中 X 日值得重点观察”，但不得无依据精确到小时。

## 七、预测语言与失效

使用“倾向、第一候选、如果 X 出现则概率提高”。每个重要预测写明会使它提前、推迟、削弱或失效的现实条件。重大新信息出现后可以重新起局，但必须按[多局比较](multi-chart-comparison.md)保留旧预测。

## 八、传统规则边界

传统资料包含值符冲合、旬空等定支方法，也明确要求结合事情远近、星门奇仪旺衰并不可执定。V1.2 因此仅将这些纳入候选池。资料与采用边界见[应期资料](../references/timing-sources.md)；实际有效性必须由前瞻台账回测。
