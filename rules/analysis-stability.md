# 分析稳定性与冻结协议

本文件是“同盘同问跨对话一致性”的强制规则。目标不是让模型机械重复措辞，而是保证：**同一局式、同一问题、同一预测起点、同一 Skill 版本，在没有新增事实时，取用、证据主次、定性等级、主趋势、关键转折和十日方向不得漂移。**

## 一、先建立分析指纹

正式分析开始前，先在内部建立 `analysis_fingerprint`。至少包含：

- 起局时间；
- 四柱；
- 阴/阳遁与局数；
- 旬首；
- 值符、值使；
- 九宫原始字段；
- 问题主体与对象；
- 目标事件；
- 预测时间范围/起点；
- Skill 版本。

只要以上字段实质相同，就视为“同盘同问”。措辞变化如“近期怎么走”“未来十日走势”“十天怎么看”不构成新问题，除非目标事件或时间范围真的改变。

## 二、固定证据账本，禁止自由联想式综合

每次分析都先形成内部 `evidence_ledger`，再定性。账本固定分四栏：

1. **主支持证据**：直接推动目标事件的高权重结构；
2. **主阻力证据**：直接阻碍目标事件的高权重结构；
3. **修正证据**：旺衰、空亡、入墓、门迫、击刑、伏吟/反吟、马星等，只修正主证据，不单独定吉凶；
4. **不确定项**：输入冲突、取用歧义、现实数据缺失。

证据优先级固定为：

`取用稳定性 + 核心宫整体 + 核心宫之间的生克/资源流向 + 落实条件`  >  `门星神干组合`  >  `旺衰与特殊状态修正`  >  `单一象意/联想`。

不得因为某次先注意到吉门、凶门、某星或某特殊状态，就改变主证据顺序。

## 三、定性采用“方向闸门”，不是印象打分

定性前必须依次回答以下五个问题：

1. **目标有没有明确推进动力？**
2. **核心阻力是否直接作用于目标或落实环节？**
3. **支持/阻力哪一侧属于更高证据层？**
4. **支持能否落实，还是只停留在意愿/表象？**
5. **特殊状态是在加强、削弱还是延迟已有主趋势？**

只有完成五问后才进入九级定性。不得先选“吉/凶”再找理由。

固定判定原则：

- 高权重支持明显占优，且落实条件完整：`吉`以上；有明显代价或阻力则下调一级。
- 支持略占优，但依赖关键条件/窗口：`平偏吉`。
- 高权重支持与阻力实质接近：`平`。
- 阻力略占优，但仍有调整路径：`平偏凶`。
- 阻力明显占优或落实链条被持续破坏：`小凶`以下。

若无法明确哪侧占优，先回到账本找缺失信息；不得以“平”掩盖未完成分析。

## 四、冻结顺序

完成分析后，按以下顺序冻结，不允许后一步反向改写前一步：

1. `取用冻结`
2. `证据账本冻结`
3. `卦象原始定性冻结`
4. `主趋势与关键转折冻结`
5. `应期/十日逐日方向冻结`
6. `现实市场/现实条件比对`
7. `最终行动建议`
8. `图片冻结字段`

其中 **现实数据只能影响第 6～8 层，不得反向修改第 1～5 层**。如果现实数据与奇门原始判断冲突，输出“冲突 + 现实风控优先”，而不是把原始定性从凶改吉或从吉改凶。

## 五、股票专项的双定性纪律

股票/ETF 必须区分：

- **卦象定性**：只来自奇门证据链，冻结后保持稳定；
- **现实执行评价**：由最新价格、量价、公告、板块与持仓背景决定，可以随时间变化。

默认用户看到的九级“等级”是 **卦象定性**。现实层只能写“现实层强化/削弱/冲突”，不得另造第二个九级等级，更不得覆盖卦象等级。

同一盘在 12:00 与 15:00 因行情变化重新查看时：

- 卦象等级、十日原始方向不变；
- 现实快照、关键价格区域、风险提示、行动建议允许变化；
- 必须说明变化来自现实数据，而不是奇门重断。

## 六、跨对话一致性检查

若当前上下文、项目案例、预测台账或用户明确引用了同一 `analysis_fingerprint` 的既有预测，正式输出前必须做一致性检查：

- 取用是否相同；
- 九级等级是否相同；
- 主趋势是否相同；
- 关键转折是否相同；
- 股票十日逐日方向是否相同。

发现不一致时，默认**不得直接发布新结论**。先定位变化来源，只允许以下五类合法原因：

1. 原始盘面被更正；
2. 问题主体/对象改变；
3. 目标事件或预测范围改变；
4. 新局替代旧局进行“新局修正”；
5. Skill 版本明确升级且规则变更足以改变结论。

若五类原因都不存在，则视为“分析漂移”，必须回退到既有冻结结论并修正当前推演。

## 七、禁止事项

- 同盘同问每次从零开始自由联想。
- 看到新行情后反推奇门原局，使原始定性迎合市场。
- 图片模型或摘要模块重新判断吉凶。
- 用星级评分、情绪词或近义词替换冻结九级等级。
- 因用户成本价高低改变标的原始走势判断。
- 新窗口没有旧答案全文时，就默认旧答案不存在；若项目上下文能检索到既有冻结结论，应优先复用并核验。
